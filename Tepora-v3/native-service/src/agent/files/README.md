# Native file-tool fixtures and deliberate differences

`source-fixtures.json` is generated by `native-service/scripts/file-tool-fixtures.mjs`
from the current `core/tools/fs.mjs` in newly-created temporary directories. It
freezes observable result text, data, errors and actual final bytes. Modification
timestamps and the temporary root are normalized only for portability. Native
unit tests separately verify mtime+size freshness, read-reference visibility and
cancellation/serialization. Node is used only to regenerate the test oracle.

The native implementation keeps sandbox mode **off** by default, and retains the
source's temporary/cwd/additional writable roots. It does not require a shell,
container, legacy-host acknowledgement, or an execution fallback for file tools.

## Deliberate security narrowing

The source checks the canonical parent plus the final filename, which can permit
an in-root final symlink targeting an outside file. It also falls back to the
lexical path when a parent does not exist. The native non-off implementation
resolves the nearest existing ancestor, checks the resulting target, rejects final
symlinks (including otherwise in-root links), and uses `O_NOFOLLOW` for the final
Unix open. Tests verify both outside-final-link and missing-parent-through-link
escapes, and verify that default-off follows source links intentionally.

This in-process path policy is **not a race-proof filesystem sandbox**. An external
actor concurrently replacing/renaming ancestor directories can still race path
validation and later filesystem calls. Final-link no-follow does not fix ancestor
renames. Hard links are also not a new access boundary. Do not claim these checks
replace an OS-enforced sandbox. Windows reparse-point handling is implemented but
not exercised by the Linux fixture gate; run platform tests before claiming it.


The process-wide mutation lock also preserves the source's **logical-path key**.
Parent-symlink aliases, hard links, or distinct JS paths that convert to the same
OS UTF-8 path may therefore reach the same file through different locks. The
same-path cross-session tests establish lexical-path serialization only; they do
not establish canonical-file/inode serialization across aliases. This inherited
limitation can permit concurrent read-modify-write loss through aliases, without
broadening writable-root permissions. No canonical/inode locking change is
included in this port.

## Explicit unavailable capability

Image filenames return a 503 unsupported native image/vision capability error;
they are never represented as a successful image read. Binary text preserves the
source's result wording; native capability metadata must separately disclose that
process/exec tools are unavailable in this slice.

## Cancellation contract

A cancelled call still waiting for the per-file lock returns `notExecuted: true`.
Once dispatched, blocking filesystem work is awaited to its real result and keeps
the lock until settlement. The coordinator must drain that result into its receipt
and keep the run lease alive; cancelling a token never proves write rollback.
