# Native local photo frame (beta.11)

The five ordinary photo-frame routes R108–R112 now run in the Rust development host, with or without `--agent`. Normal Node/Tauri launch and the JavaScript/CSS UI are unchanged. This is a scoped port, not a default-switch or full migration claim.

## Contract

- `GET /api/frame`: ordered public metadata and original limits
- `PUT /api/frame/photos`: raw, inert bytes, signature/dimension inspection, SHA-256 duplicate suppression and local persistence
- `GET` / `HEAD /api/frame/photos/{uuid}`: original byte content, MIME/length, private one-hour cache and restrictive photo CSP
- `DELETE /api/frame/photos/{uuid}`: delete the file, update the ordered list and publish `frame.updated`

The compatibility contract is 24 MiB per photo, 300 photos, 2 GiB total and 120 million cheaply-read pixels. JPEG/PNG/GIF/WebP/AVIF signature handling preserves source behavior, including unknown dimensions and the source's malformed-PNG errors. No decoder, renderer, remote fetch, user-photo scan or file upload to an external service is added. Names follow host-platform basename handling, ECMAScript trimming and 120 UTF-16-unit clipping. Public snapshots omit hashes and on-disk extensions.

The existing HTTP owner still authenticates every request and retains Host/Origin/CSRF checks. Body admission is bounded before the typed domain operation is dispatched. A dedicated photo mutex serializes list/file operations, including concurrent identical imports; SQLite remains owned by the one Workspace connection and is not locked across filesystem I/O. Writes use an exclusive temporary file and rename, with best-effort temporary-file cleanup on write/rename failure (cleanup itself can fail). Already-admitted photo work can finish its metadata/event commit after close admission is withdrawn; final shutdown waits for the photo mutex before closing SQLite. Duplicate imports emit no event. A missing file reads as 404 and can still be removed from the list. Other display reset/import operations leave the photo library untouched.

This port preserves existing metadata/file layout and does not migrate data. As in the compatibility host, filesystem changes and the SQLite metadata commit are not one cross-resource transaction: a process crash between them can leave an unreferenced file or stale metadata. It does not claim crash-time reconciliation. Avatar asset packs, speech and media effects remain separate work.

## Verification

The added fixtures use generated byte arrays and temporary directories only. `scripts/frame-source-fixtures.mjs` generates 56 frozen signature/dimension/error cases plus filename cases for both POSIX and Windows path rules from the Node source. Rust tests exercise those fixtures, byte/read/delete/restart behavior, ordered snapshots/events, 12 concurrent identical imports, count/total/individual limits, ordinary filesystem failures and deterministic add/delete shutdown ordering.

`tests/rust-photo-frame.test.mjs` starts the native binary by absolute path with an empty PATH and synthetic home/data directories. It compares ordinary imports with the source `PhotoFrame`, checks HTTP GET/HEAD, duplicate imports, event replay, display reset/import isolation, restart, missing-file cleanup and the exact 24 MiB upload boundary. Nothing in this fixture calls a model or external service.

Local Linux evidence (2026-10-08): 8 focused Rust tests pass; the two process-level HTTP tests pass under both Node 22.16.0 and 24.19.0. The HTTP tests cover workspace mode and native-agent mode. The 56 generated source cases and both-platform filename fixtures are byte-identical under those Node versions. Core/native builds, changed JavaScript syntax checks and route-inventory counts pass. Integration with the scheduler/lifecycle baseline also passes 71 selected ordinary native-service tests and, under both Node 22.16.0 and 24.19.0, 13 HTTP tests, 1 source scheduler regression and9 root checks. These are focused checks; the aggregate quality gate and broader suites were not rerun for this candidate. Preceding f0d6c43 passed all five CI jobs including Windows installation/startup and macOS DMG/bundled startup, which do not certify this added photo slice.

Commands (build the native core first, as for other Node tests):

```sh
npm run build:core
cargo test --locked --manifest-path Tepora-v3/native-service/Cargo.toml photo_frame --lib
cargo build --locked --manifest-path Tepora-v3/native-service/Cargo.toml
TEPORA_NATIVE_SERVICE_BINARY=/absolute/path/to/tepora-native-service node --test Tepora-v3/tests/rust-photo-frame.test.mjs
```

Resource scope: no new dependency or background task. Signature checks are bounded by the admitted image length; bytes are retained for the one import/read and never decoded into a pixel buffer. Limits bound stored bytes, not the number of simultaneous HTTP body buffers. This slice makes no performance-improvement claim and has not exercised personal photos, GPU/browser rendering, desktop packaging or real-model behavior. Broader approval-policy/security suites are outside this slice.
