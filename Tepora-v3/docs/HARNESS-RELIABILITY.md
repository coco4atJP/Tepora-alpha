# V3 ハーネス改善・検証記録 — beta.11

対象は `rust/v3-core-migration` の `2a30c5a` を基点とする修正です。調査で再現した失敗を回帰試験にし、通常のNodeホストと、既存機能が対応するRust開発ホストを修正しています。正式版への切り替えや、実モデルの能力評価は別の受け入れ条件です。

## 改善した動作

| 対象 | 修正後の動作 | 主な検証 |
| --- | --- | --- |
| 文脈圧縮 | 出力上限で途切れた要約やツール呼び出し付きの要約を採用せず、決定的なフォールバックへ進む。失敗した要約の使用量も残す | Node / Rustの圧縮試験 |
| ファイル再読込 | 文脈に収まらなかった結果や、1行2,000文字で切れた結果を「全文表示済み」として再利用しない。行単位の省略を明示する | 再読込・証拠取得・UTF-16境界 |
| 予算 | 通常呼び出しの既知費用に加え、要約などの補助呼び出しの既知費用を次ステップの予算判定に反映する | セッション・日次上限、重複計上なし |
| プロジェクト指示 | 初回推論前に、リポジトリルートから作業ディレクトリまでの `.agents/AGENTS.md` と `AGENTS.md` を共有Rust実装で読む | 初回リクエスト、親子の順序、変更・削除 |
| 追加入力 | `steer` は次ステップ、`followup` は現在のターンが終わってから1件ずつ、`notify` は受動的な情報として配信する | 実行中の入力、停止・再開、原子的な取り出し |
| 予約タスク | 起動に失敗した予約を消さず、エラーと60秒後の再試行時刻を残す。同じ予約ID・予定時刻の再試行は、受理済みワーカーを再利用する | 起動失敗、記録失敗後の再試行、Rustスケジューラー |
| PC操作の完了条件 | 配列内だけでなく、同じチェックオブジェクト内の条件もすべて満たす必要がある。不正な条件は操作前に拒否する | URL・本文・フィールド値・チェック状態 |
| PC操作の進行判定 | スクロール位置、表示範囲、本文の変化を進行として扱う。操作対象の鮮度確認と本文の変化を区別する | 長いページの末尾まで進めること |
| アプリ起動 | macOSアプリを起動してから、ウィンドウの出現を期限付きで待つ | ランチャーとウィンドウ列挙の代替実装 |
| ブラウザのダイアログ | CDPのalert/confirm/promptを自動承認しない。観測したIDと明示的な応答が必要 | CDPイベントと応答の代替トランスポート |
| 操作中断 | 再観測やモデル応答の後にも中断を確認し、次の操作を開始しない | 再観測中・CDP送信間の中断 |
| 長文入力の照合 | 表示用の200文字プレビューとは別に、DOMまたはAXの実際の値をローカルで比較し、真偽値だけを返す | 長文、空白・改行、末尾相違 |
| 評価器 | JSONの値・配列件数、完全一致のファイル、実行記録、正常完了を確認する。成果物は評価対象セッションに限定し、失敗・未実施は非0で終了する | ローカルHTTPモデル代替とCLI終了コード |

## 実装上の境界

- 入力の取り出しは、ログ・検索索引への追記と受信箱からの削除を、既存のSQLite所有者による1トランザクションで処理する。通常のチャット・音声入力は `steer`、明示的なワーカーへの追加依頼は従来のAPI既定どおり `followup`。
- プロジェクト指示は最寄りの `.git` まで最大64階層を探索する。リポジトリが見つからなければ作業ディレクトリ内だけを読む。各階層では `.agents/AGENTS.md`、`AGENTS.md` の順で、深い階層の指示を優先する。自動読み込みはUTF-8、1ファイル16 KiB、合計32 KiBまで。範囲外へのシンボリックリンク・サイズ超過・読込失敗は明示する。
- 指示の変更・削除は次のプロンプト準備時に通知を追記し、システムプロンプト自体はチェックポイントで更新する。作業ディレクトリより深い編集先の指示は、モデルが追加で読む必要がある。すべてのshell/MCP編集先に対する自動的な適用強制までは実装していない。
- `computer` の `dialog` は `dialog_id` と `accept: true/false` を要求する。promptへの入力には `text` を使う。判断モデル方式だけを有効にしている場合も、この明示的な応答は利用できる。既存の操作権限を追加で付与するものではない。
- 中断チェックは操作の送信境界を対象とする。すでにOSやアプリへ送信されたクリック・キー入力・外部処理を取り消せる保証はない。
- 予約の重複防止はワーカーの受理単位であり、外部アプリに対する副作用のexactly-once保証ではない。リマインダーや外部送信の重複防止は別途必要。
- 費用は観測済みの推定額に基づく。過去の費用の補完、未報告の使用量、処理中の予約額、同時実行の厳密な上限は未対応。[会計仕様](RUST-MODEL-USAGE.md)を参照。

## 再現手順

```sh
npm run build:core
npm run test:rust
npm run test:native
node --test Tepora-v3/tests/agent-reliability.test.mjs Tepora-v3/tests/computer-reliability.test.mjs Tepora-v3/tests/eval-agent.test.mjs
npm run quality
```

共有のCargo出力先を使う場合、プロセス試験には `TEPORA_NATIVE_SERVICE_BINARY` で実際のネイティブ実行ファイルを指定する。ブラウザ・bwrapの実行可否はホスト環境にも依存する。モデル代替の試験合格は、実モデル・実デスクトップでの成功を意味しない。最新の検証結果は[QA](QA.md)に記録する。

## 正式化前に続ける改善

1. **Windows/macOS実機の操作基盤**：Windows UI Automation、macOS AXの実機回帰、画像・座標の代替経路、複数画面、フォーカス、権限拒否、ユーザーの同時操作を検証する。Rust開発ホストのComputer Useは依然未対応。
2. **開発タスクの実行基盤**：編集先ごとの指示の自動適用、PTY・長時間プロセス、差分とテスト結果の構造化、作業領域の分離、LSPによる診断を順に揃える。
3. **長時間常駐の負荷対策**：多数の完了済みセッションを含むruntime factsの転送量を減らし、ステップごとの遅延・メモリを測定する。予約処理や外部副作用の再起動試験を拡充する。
4. **比較可能な実モデル評価**：モデル・設定・予算・課題・採点器を固定し、Pi、DeepSeek Harnessなどと開発タスクを比較する。PC操作は別のWindows/macOS課題群で成功率・介入回数・時間・費用を測る。

今回の変更だけでは、一般的なPCタスクをすべて実行できることや、他のハーネスに対する成績上位を示せない。
